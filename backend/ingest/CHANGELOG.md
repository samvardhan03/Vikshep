# Changelog — vikshep-ingest

## 0.4.1

- **Fix: the recipes reported training-set metrics.** `vikshep-recipe tag` and
  `calibrate` fit on every event and scored the same events, so the reported
  AUC, dCorr², R² and residual std measured memorisation. With 217 noise
  features, a ridge fit to a noise target gives R² 1.0 on 120 events and
  about 0.2 on 1000; a tagger on random labels gives AUC about 0.9 and 0.75.
  On the 1000-event quickstart the 0.4.0 numbers were training values:
  calibrate R² 0.5589 is −1.1343 held out; tag AUC 0.9743 and dCorr² 0.0182 at
  `--lambda 1` are 0.9496 and 0.0102 held out.
- **Held-out metrics** from seeded K-fold cross-validation (new
  `vikshep_ingest.heldout`, fold scheme `vikshep.kfold/1`: events ordered by
  SHA3-256 of the seed and their index, dealt round-robin into folds,
  stratified by label for `tag`; no numpy random generator, so the folds are
  the same on every platform). New options `--folds` (default 5) and `--seed`
  (default 42, also the training seed, as before). Calibration predictions on
  held-out events reproduce the core's arithmetic bit for bit, and metric sums
  are exactly rounded, so the reports stay byte-identical across platforms.
- **Report fields renamed** so no number can be mistaken for the other kind:
  tag `auc` and `dcorr2` are now `auc_heldout`, `dcorr2_heldout`, `auc_train`
  and `dcorr2_train`; calibrate `r2_score` and `residual_std` are now
  `r2_heldout`, `residual_std_heldout`, `r2_train` and `residual_std_train`.
  New fields: `evaluation` (method, fold scheme, folds, seed, stratification,
  per-fold values), `n_features` and `warnings`.
- **Small-sample warning:** the recipes warn, on stderr and in `warnings`,
  when the training folds hold fewer than 10 events per feature, and more
  strongly when they hold no more events than features.
- An undefined dCorr² (fewer than 4 background events) is now `null`, not 0.
- The benchmark harness (`python -m bench.run`, repository only) computes
  AUC, dCorr², the Asimov proxy and JSD on out-of-fold scores, and gains
  `--folds`.
- Golden report hashes regenerated.

## 0.4.0

- **First PyPI release** (`pip install vikshep-ingest`), published by
  `.github/workflows/release-ingest.yml` from an `ingest-v*` tag.
- **The open core is a regular dependency**: `vikshep-compute==0.1.0` from
  PyPI (prebuilt wheels; no Rust toolchain) on Linux x86_64 and aarch64,
  macOS and Windows x86_64. Elsewhere the recipes fall back to aggregates as
  before; the `[scattering]` extra now requests the PyPI core rather than a
  git build. `vikshep-compute` 0.1.0 equals the previously pinned commit
  `b55468b` numerically (`numerics_version = 3`); it adds the certificate
  verifier.
- Package metadata: README, licence expression, project URLs, classifiers.
- **`vikshep-ingest sim RUN [RUN ...] [--signal RUN ...] [--out DIR]`**: reads
  vikshep-sim output folders (hits.arrow format v1, through pyarrow:
  `pip install "vikshep-ingest[sim]"`), checks each run's OID against its
  run_summary.json, maps hits to the grid and aggregates of the CSV path (phi
  and theta from the gun position, momentum and energy in GeV) and adds the
  event columns run_index, primary_energy_GeV, primary_pdg and, with
  `--signal`, is_signal. The scattering recipes rebuild the grids from the run
  folders when the shared-memory segments are gone. Checked against the
  vikshep-sim golden files (their recorded OIDs are reproduced).
- **Fix: the scattering recipes trained on blank images.** When the ingest
  process had exited (always the case from the CLI), `load_grids`
  re-rasterized from `source_path` but read the grids back after the adapter
  had unlinked them, and substituted zeros for every event. Calibrate and tag
  on the scattering path therefore learned nothing (R² 0, AUC 0.5); the
  golden hashes matched across platforms because blank inputs are
  deterministic too. The grids are now read while the adapter is open, and a
  CSV that changed after ingest is refused.
- **Fix: label, target and protected columns leaked into the features.** On
  the aggregates path, `vikshep-recipe` and the benchmark harness trained on
  every aggregate, including the columns named by `--label`, `--protect`,
  `--weights` or `--target` (for example `--target layer1_e_mean` gave R² 1).
  Those columns, and event columns, are now excluded.
- **Event columns:** an extra CSV column with one numeric value per event (a
  truth label, the incident energy, an MC weight) is kept per event and listed
  in `event_column_names`; other extra columns are still ignored with a warning.
- **Feature cache:** scattering features are cached next to the manifest
  (`.vikshep-cache/`), keyed by the grid OIDs, configuration and core version,
  so `tag` after `calibrate` reuses them (same bytes).
- **Quickstart sample:** a synthetic 1000-event sample with `is_signal`,
  `true_energy` and `weight`, generated by `examples/g4_quickstart/make_sample.py`,
  replaces the 10-event file; golden hashes regenerated.


## 0.3.0

- **Scattering extra** (`pip install -e "backend/ingest[scattering]"`): wires
  in the open deterministic core
  [`samvardhan03/vikshep-compute`](https://github.com/samvardhan03/vikshep-compute)
  (pinned to commit `b55468b`, `numerics_version = 2`).  Requires a Rust toolchain.
- **`vikshep-recipe tag` and `calibrate`** gain `--feature-set {scattering,aggregates,both,auto}`.
  With `scattering`: loads 64×64 (phi×theta) grids from named POSIX shm (OID = segment name),
  runs the wavelet scattering transform (J=3, Q=1, L=8, pad=[Circular, ZeroPad]), computes
  r2 ratios, and trains with the exact weighted dCorr² gradient from the core.
  Default is `scattering` when `vikshep_compute` is importable, else `aggregates` with a notice.
- **Provenance**: every CLI run writes `provenance.json` (VDS-1 schema from the open core)
  next to its outputs.
- **Report fields**: `feature_set` and `training_gradient` (`"exact_weighted"` or
  `"pearson_proxy"`) are now present in every tag and calibrate report.
- **Shared-memory naming**: `G4Adapter` now names shm segments with the OID (28-char hex)
  so downstream tools can look them up without additional tracking.  `source_path` is recorded
  in the manifest for shm-recovery re-rasterization.
- **Bench harness**: uses `vikshep_compute` (exact dCorr², exact gradient, Adam training) when
  installed; falls back to the pure-Python path.  Report records `statistics_backend` and
  `training_gradient`.
- **`McpClient.ts`**: looks for `VIKSHEP_MCP_BIN` first, then `OMNIPULSE_MCP_BIN` (deprecated
  alias, logs a warning), then PATH.  Error message points at building `vikshep-mcp` from the
  open core.

## 0.2.0

- **Geant4 Direct Interface** (`vikshep_ingest.g4`): CSV ingest adapter for
  Geant4 output, `komal_v1` profile (per-hit rows of event_id, layer, phi,
  theta, momentum, energy), generic profile with `--column-map`, per-event
  rasterization to 2-D (phi × theta) grids with correct PadPolicy assignment,
  automated per-layer aggregate scalars (the manual pandas quantities),
  malformed-row accounting, shared-memory registration under 28-char SHA3-256
  OIDs.
- **Shared pad policy** (`vikshep_ingest.pad_policy`): single source of truth
  for periodic→Circular, wall→ZeroPad, open→ZeroPad, used by both the G4
  adapter and the upcoming Well adapter.
- **Weighted DisCo** (`vikshep_ingest.disco`): exact weighted Szekely-Rizzo
  distance correlation; chunked estimator for n > 10k events.
- **Console scripts**: `vikshep-ingest g4` and `vikshep-recipe tag / calibrate`.
- **Dependencies**: added scipy, pandas, scikit-learn for the recipe runners
  and tests.
